# Windows 런처 재구현 설계안

상태: 2026-11-11 사용자 승인, 구현 진행 중. 기존 문서의 COMPLETED 표시는 이 설계의 완료 근거로 사용하지 않는다.

## 목적과 성공 기준

Windows에서 설치해 매일 사용할 수 있는 macOS 스타일 런처를 만든다. 실제 앱 아이콘, 검색 결과, 실행 및 창 전환이 정상 작동해야 한다. macOS와의 시각적 유사성은 실제 화면과 동작을 비교해 개선한다. 테스트 수와 API 호출 성공만으로 제품 완성을 선언하지 않는다.

사용자가 요청한 것은 기존 결과를 제대로 구현하기 위한 계획과 진행이다. 아래 기술 선택과 기본값은 작성자의 제안이며 사용자 승인 사실로 취급하지 않는다.

## 접근 방식

1. **기존 Rust/Win32 기반을 기능별로 재구현 — 권장.** 수학 코어와 유효한 Windows 연동 코드를 유지하고 실제 화면 및 앱 모델을 연결한다. 기존 코드의 mock 혼입과 렌더링 소유권 문제를 함께 정리해야 한다.
2. **새 Rust 프로젝트로 전면 재작성.** 경계를 처음부터 만들 수 있으나 창 생성, 검색, 배포까지 재작업하게 된다. 현재 확인한 결함만으로 전면 재작성 비용을 정당화하기 어렵다.
3. **다른 UI 프레임워크로 교체.** 일반적인 설정 화면은 빨리 만들 수 있으나 투명 창, DWM 썸네일, 입력 처리와 DPI를 다시 검증해야 한다. 현 단계에서는 보류한다.

## 범위와 기본 동작

- Windows 10/11 x64가 첫 지원 대상이다. ARM64는 별도 빌드와 실기 검증 전까지 지원으로 표기하지 않는다.
- Rust + Win32 + Direct2D/DirectComposition을 유지한다. Electron/WebView 런타임은 추가하지 않는다.
- 첫 사용 가능한 버전은 Dock와 Spotlight다. 메뉴바와 Stage Manager도 후속 단계에 포함한다. 완성 전에는 기본 실행에서 비활성화하며 설정에서 준비 상태를 표시한다.
- Windows 작업표시줄은 기본 유지한다. 숨김 옵션은 복원 경로와 실제 종료/충돌 검증을 마친 뒤 제공한다.
- 실제 설치된 Windows 앱 이름과 아이콘을 사용한다. Safari 이름으로 Edge를 실행하는 식의 고정 대응을 제거한다.
- 목표 외형은 기존 macOS 스타일이다. 특정 macOS 버전의 픽셀 단위 복제를 완료 조건으로 삼으려면 기준 화면과 버전을 먼저 고정해야 한다.
- 기존 README의 35MB/0% CPU/120Hz 수치는 측정 전까지 목표로만 표시한다.

## 구조와 소유권

`main.rs`는 시작, 종료, 오류 보고를 담당한다. 실행 조립은 `runtime.rs`, 사용자 설정은 `settings.rs`, 앱 목록은 `app_catalog.rs`, 아이콘은 `icon_cache.rs`, 모니터 좌표는 `display.rs`로 분리한다. 기존 view 파일은 사용자 입력과 표시 상태를 소유한다.

- **앱 목록:** 안정적인 앱 ID, 표시 이름, 실행 대상, 아이콘 원본, 실행 프로세스 연결 정보를 한곳에서 관리한다. 시작 메뉴 바로가기와 Windows 앱 목록을 수집하고 Dock와 Spotlight가 같은 데이터를 사용한다. 실행 경로와 표시 이름을 식별자로 혼용하지 않는다.
- **설정:** `%LOCALAPPDATA%/MacLauncher/settings.json`에 버전, 고정 앱 순서, Dock 크기, 대상 모니터, 단축키, 선택 기능을 저장한다. 파일이 잘못되면 원본을 보존하고 복구 방법을 로그에 남긴다. 원자적 교체로 저장한다.
- **렌더링:** GPU 장치는 공유하고 창별 composition target/visual/surface를 명시적으로 소유한다. BeginDraw에서 받은 컨텍스트에 그리며 EndDraw와 commit을 보장한다. surface 크기 변경, DPI 변경, device lost 복구 경로를 둔다. 프로덕션 초기화 실패를 mock 성공으로 바꾸지 않는다.
- **아이콘:** Shell에서 실제 아이콘을 얻어 알파를 보존한 비트맵으로 변환한다. 앱 ID와 해상도로 캐시하고 GPU 장치 재생성 시 GPU 자원을 다시 만든다. 추출 실패 시 식별 가능한 대체 아이콘과 앱 이름을 제공한다.
- **모니터:** 논리 좌표(DIP)와 물리 픽셀 변환을 한곳에서 수행한다. Per Monitor DPI awareness, 음수 모니터 좌표, 작업영역, 해상도와 배율 변경을 처리한다.
- **입력과 수명:** 투명한 빈 영역은 뒤쪽 앱 입력을 막지 않는다. 트레이에 설정/종료를 제공하며 중복 실행을 방지한다. 기본 화면에 콘솔을 띄우지 않고 파일 로그로 오류를 진단한다.
- **재그리기:** 입력, 상태 변경, 진행 중 애니메이션에 따라 그린다. 정지 상태에서 모든 화면을 무조건 다시 그리는 루프를 제거한다. 60/120/144Hz는 실제 디스플레이 주기에 맞추고 측정한다.

## 구현 순서와 단계별 완료 기준

### 1. 실행 기반과 검증 경계

대상: `main.rs`, `runtime.rs`, `directx.rs`, 각 `*_window.rs`, CI.

실제 실행에서 mock 대체를 제거하고 선택 기능 초기화 실패를 명시적으로 보고한다. 공통 렌더링 surface 수명과 장치 소유권을 정리한다. 트레이 종료, 중복 실행 방지, 파일 로그, DPI 선언을 추가한다. 기존 README와 SESSION_CONTEXT의 완료/성능 주장을 실제 상태로 갱신한다.

완료: Windows에서 Dock가 표시되고 트레이로 종료할 수 있다. 시작 실패 원인이 로그에 남는다. Windows 전용 코드가 실제 Windows CI에서 빌드되고 명시적 실제 backend 검사를 통과한다.

### 2. 앱 목록과 실제 Dock

대상: `app_catalog.rs`, `icon_cache.rs`, `settings.rs`, `display.rs`, `dock_view.rs`, `directx.rs`, `app_tracker.rs`, `process_launcher.rs`.

실제 앱 목록에서 초기 고정 앱을 선택하고 아이콘을 렌더링한다. 우클릭으로 앱 고정/해제, 실행 중 앱 고정, 순서 변경과 설정 저장을 제공한다. 실행 실패를 사용자에게 알린다. 바로가기, 프로토콜, 일반 exe의 실행과 기존 창 활성화를 구분한다. 다중 창은 선택 목록으로 전환한다.

완료: 설치된 앱 아이콘을 구별할 수 있고 클릭으로 올바른 앱이 열린다. 한글/공백 경로, 존재하지 않는 대상, 최소화된 창, 다중 창을 검증한다. 재시작 후 고정 목록이 유지된다. 100/150/200% 배율, 보조 모니터, 작업표시줄 유지 상태에서 배치와 클릭 좌표가 맞는다.

### 3. 실제 Spotlight

대상: `indexer.rs`, `spotlight_view.rs`, `spotlight_window.rs`, `spotlight_render.rs`, `runtime.rs`.

공유 앱 목록을 검색하고 실제 surface에 검색어, 앱 이름, 아이콘, 선택 표시를 그린다. IME 한글 조합, 붙여넣기, 키보드/마우스 선택을 지원한다. Enter 실행, Escape/포커스 이탈 닫기, 계산 결과의 실제 클립보드 복사를 연결한다. 단축키 충돌은 설정과 오류 표시로 해결한다.

완료: 단축키 → 한글/영문 검색 → 결과 표시 → 실행 → 닫기가 실제 Windows에서 연결된다. 빈 결과, 긴 검색어, 긴 앱 이름, 단축키 충돌, 반복 열기/닫기와 크기 변경을 검증한다.

### 4. 메뉴바

대상: `menu_bar_*`, `system_status.rs`, `runtime.rs`.

실제 화면 렌더링을 연결한다. 일반 Windows 앱의 메뉴를 macOS처럼 완전히 가져올 수 있다고 가정하지 않는다. 앱 이름과 실행 가능한 시스템 명령만 제공하고 동작 없는 메뉴 항목을 제거한다. AppBar 예약 영역과 dropdown 크기를 분리한다.

완료: 실제 상태/시간이 표시되고 모든 노출 메뉴 명령이 동작한다. 최대화/전체화면/작업표시줄/다중 모니터에서 예약 영역을 검증하고 종료 후 원상 복원된다.

### 5. Stage Manager

대상: `stage_*`, `dwm_thumbnail.rs`, `runtime.rs`.

선반의 실제 렌더링과 썸네일을 연결한다. 표시/입력 영역이 함께 이동하게 하고 기존 창 상태와 실제 foreground 상태를 동기화한다. 최소화, 종료된 창, 자체 창 제외를 처리한다. 사용자 활성화 전에는 다른 앱을 최소화하지 않는다.

완료: 선반 표시, 라이브 썸네일, 그룹 전환, 창 종료/추가가 실제 Windows에서 동작한다. 선반을 접었을 때 바탕화면 입력을 막지 않는다.

### 6. 배포와 성능

대상: `.github/workflows/`, `installer/`, `README.md`, 검증 문서.

테스트한 동일 빌드로 설치/업데이트/제거를 검증한다. 버전 정보를 Cargo와 설치 패키지에서 일치시킨다. 자동 시작은 명시적 선택으로 제공한다. 태그만으로 정식 완성 릴리스를 내지 않고 Windows 실기 검증 결과를 함께 기록한다.

완료: 깨끗한 Windows 사용자 계정에서 설치, 실행, 재부팅, 업데이트, 제거가 성공한다. 유휴/애니메이션/검색 시 CPU·RAM·프레임 시간을 기록한다. 측정 환경과 미검증 조건을 배포 문서에 남긴다.

## REA와 외형 비교

현재 추출기는 plist 키 조회와 기본값 fallback이다. 바이너리에서 애니메이션 상수를 확인했다는 근거로 취급하지 않는다. 추출 결과에는 원본 경로, OS 버전, 조회한 키, 관측값/기본값 구분을 기록하고 런처 설정에 실제 반영한다. 외형 조정은 기준 Mac에서 정지 화면과 hover/launch 동영상을 수집하고 Windows 결과와 비교한다. REA 본체 변경은 필요한 조회가 실제로 불가능하다고 확인된 경우에 별도 판단한다.

## 검증과 작업 기록

- 순수 모델 테스트: 앱 ID, 정렬/검색, 설정 왕복, 좌표 변환, 배치, 애니메이션.
- Windows 통합 테스트: Shell 앱 열거/아이콘, 실제 렌더러 초기화, window/surface resize, 클립보드와 실행 결과. OS 동작을 바꾸는 검사는 명시적으로 분리한다.
- Windows 수동 검증: 실제 표시, 한글 IME, 입력 통과, focus, DPI와 모니터 이동, sleep/resume, GPU 복구, 설치/제거. 날짜·빌드 SHA·환경·결과를 기록한다.
- macOS 테스트 통과는 Windows UX 검증으로 기록하지 않는다. Windows 런타임을 사용할 수 없으면 해당 단계는 미검증 상태로 남긴다.

각 단계는 작은 변경 단위로 구현하고 적절한 테스트 및 Windows 빌드를 거친다. 기능을 화면에서 확인할 수 있는 시점마다 사용자가 검토할 수 있는 설치 패키지를 준비한다. 공개 배포와 커밋은 별도 요청 또는 합의된 저장소 절차에 따른다.
